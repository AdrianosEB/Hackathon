# Ghost Network — Engineering Plan
## Hackathon MVP · 12 Hours · 5 Engineers

*Generated by /plan-eng-review — 2026-08-21. Branch: ghost-network-fraud-detection-ai.*

---

## Synopsis

Ghost Network is an AI platform that detects fraudulent provider directories in health insurance networks. Insurers routinely list doctors who are retired, unreachable, or not actually accepting patients on the listed plan — inflating their network adequacy metrics to claim public funding. This MVP proves the core thesis in 12 hours: ingest a provider dataset, flag discrepancies algorithmically, then have an AI voice agent call flagged providers pretending to book an appointment for a real member on a real plan. If the number is disconnected, the doctor doesn't work there, or the practice isn't accepting that plan — it's a ghost. Results land in a live dashboard with a one-click audit report export.

The architecture is a four-layer pipeline: a Python data script produces a list of flagged providers, a FastAPI backend stores them in SQLite and orchestrates calls via Vapi.ai, a React frontend shows the live classification results, and an HTML audit template turns the evidence into a printable report. Vapi.ai handles telephony and transcription; Claude claude-haiku-4-5 classifies the transcript into one of four outcomes (CONFIRMED / GHOST / NOT_ACCEPTING / NO_ANSWER).

**Engineer roles:**
- **Eng 1 (Data)** — fetch 500 providers from the NPPES public API, generate a synthetic insurer directory with 30 planted discrepancies, run the flagging script
- **Eng 2 (Voice Agent)** — build the Vapi.ai call dispatcher, the Claude transcript classifier, and the webhook handler; test real calls
- **Eng 3 (Backend)** — scaffold the FastAPI app and SQLite schema, wire all REST endpoints, seed from Eng 1's data
- **Eng 4 (Frontend)** — build the React dashboard (stats card, provider table, detail panel with transcript + trigger-call button)
- **Eng 5 (Audit + Integration)** — build the printable audit report template, then at hour 8 wire all four layers together and own the demo dry-run

## Stack Decisions (with rationale)

| Layer | Choice | Why |
|---|---|---|
| Voice API | **Vapi.ai** | Real-time monitoring dashboard lets judges watch calls live. Cleaner webhooks than Bland.ai. Python SDK. Free tier covers 10 demo calls. |
| Backend | **FastAPI + Python** | Same language as data pipeline (no context switch). Async-native for webhook handlers. Pydantic validation catches bad Vapi payloads at the boundary. Auto-docs at `/docs` for demo. |
| Database | **SQLite** (stdlib `sqlite3`) | Zero infra setup. File-based — portable between machines. Holds 500 providers + 50 calls without breaking a sweat. |
| Frontend | **React + Vite + Tailwind CSS** | Vite scaffolds in 30 seconds. No SSR complexity. Tailwind via PostCSS (not CDN — avoids runtime slowness during demo). |
| AI Classifier | **Claude API — claude-haiku-4-5** | $0.001/1K tokens. 200ms P95 latency. Reliable JSON output with structured tool use. Keyword fallback if quota runs out. |
| Tunnel | **ngrok** | Vapi webhooks need a public HTTPS URL. ngrok free tier is fine; stable URL with `--domain` flag if they have a paid account. |
| Environment | **python-dotenv + .env** | Single `.env` file for all secrets: `VAPI_API_KEY`, `ANTHROPIC_API_KEY`, `NGROK_URL`. |

`backend/vapi_client.py`
```python
import os, requests

VAPI_BASE = "https://api.vapi.ai"
HEADERS = {"Authorization": f"Bearer {os.environ['VAPI_API_KEY']}"}

CALL_SCRIPT_TEMPLATE = (
    "Hi, I'm calling from {plan_name} member services. "
    "I have a member, {member_name}, who's looking to schedule "
    "an appointment with {provider_name}. Can you confirm "
    "the practice is still accepting new patients on {plan_name} plans?"
)

def trigger_call(provider: dict, plan_name: str, member_name: str) -> dict:
    """
    Dispatches an outbound call via Vapi.ai.
    Returns {"call_sid": str, "status": str}
    """
    script = CALL_SCRIPT_TEMPLATE.format(
        plan_name=plan_name,
        member_name=member_name,
        provider_name=provider["name"],
    )
    payload = {
        "phoneNumberId": os.environ["VAPI_PHONE_NUMBER_ID"],
        "customer": {"number": provider["phone"]},
        "assistant": {
            "firstMessage": script,
            "model": {"provider": "openai", "model": "gpt-4o-mini"},
            "voice": {"provider": "openai", "voiceId": "alloy"},
            "endCallAfterSilence": 20,
            "maxDurationSeconds": 120,
        },
        "serverUrl": f"{os.environ['NGROK_URL']}/vapi/webhook",
    }
    r = requests.post(f"{VAPI_BASE}/call", json=payload, headers=HEADERS, timeout=15)
    r.raise_for_status()
    data = r.json()
    return {"call_sid": data["id"], "status": data["status"]}

def get_call_status(call_sid: str) -> dict:
    r = requests.get(f"{VAPI_BASE}/call/{call_sid}", headers=HEADERS, timeout=10)
    r.raise_for_status()
    return r.json()
```

#### Hour 1–3: Transcript classifier

`backend/classifier.py`
```python
import anthropic, os, json

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])

SYSTEM_PROMPT = """You are a medical network adequacy auditor.
Classify this call transcript into exactly one category:
- CONFIRMED: provider confirmed accepting new patients on this plan
- GHOST: number disconnected, not a medical office, or provider doesn't exist there
- NOT_ACCEPTING: practice exists but not accepting new patients or not on this plan
- NO_ANSWER: voicemail, no answer, or call not connected

Return JSON only: {"classification": "...", "confidence": 0.0-1.0, "excerpt": "...15-word supporting quote..."}"""

def classify_transcript(transcript: str) -> dict:
    """
    Calls Claude claude-haiku-4-5 to classify a call transcript.
    Falls back to keyword matching if API fails.
    """
    try:
        msg = client.messages.create(
            model="claude-haiku-4-5-20251001",
            max_tokens=200,
            system=SYSTEM_PROMPT,
            messages=[{"role": "user", "content": f"Transcript:\n{transcript}"}],
        )
        return json.loads(msg.content[0].text)
    except Exception:
        return _keyword_fallback(transcript)

def _keyword_fallback(transcript: str) -> dict:
    t = transcript.lower()
    if any(w in t for w in ["not in service", "disconnected", "wrong number"]):
        return {"classification": "GHOST", "confidence": 0.7, "excerpt": transcript[:80]}
    if any(w in t for w in ["not accepting", "closed panel", "not taking"]):
        return {"classification": "NOT_ACCEPTING", "confidence": 0.7, "excerpt": transcript[:80]}
    if any(w in t for w in ["yes", "accepting", "available", "schedule"]):
        return {"classification": "CONFIRMED", "confidence": 0.6, "excerpt": transcript[:80]}
    return {"classification": "NO_ANSWER", "confidence": 0.5, "excerpt": ""}
```

#### Hour 3–4: Webhook handler

`backend/webhook.py`
```python
from fastapi import APIRouter, Request
from .classifier import classify_transcript
from .db import save_call_result

router = APIRouter()

@router.post("/vapi/webhook")
async def vapi_webhook(request: Request):
    payload = await request.json()
    event_type = payload.get("message", {}).get("type")

    if event_type == "end-of-call-report":
        msg = payload["message"]
        transcript = msg.get("transcript", "")
        call_sid = msg.get("call", {}).get("id", "")
        provider_id = msg.get("call", {}).get("metadata", {}).get("provider_id", "")

        result = classify_transcript(transcript)
        save_call_result({
            "provider_id": provider_id,
            "call_sid": call_sid,
            "classification": result["classification"],
            "confidence": result["confidence"],
            "transcript_excerpt": result["excerpt"],
        })
    return {"status": "ok"}
```

            provider_id TEXT PRIMARY KEY,

## Architecture Review Findings

### Finding 1 — ngrok URL drift [P2, confidence 9/10]

Vapi calls `serverUrl` at trigger time. If ngrok restarts (e.g., engineer closes terminal), the URL changes and webhook calls fail silently — calls go through, transcripts arrive at nowhere, UI shows calls stuck in "PENDING."

**Fix:** Set ngrok URL once in `.env` (`NGROK_URL`). Add a startup health check in `backend/main.py` that pings `{NGROK_URL}/health` and warns if unreachable. Assign the URL at demo start and don't restart ngrok.

### Finding 2 — Vapi call metadata not forwarded [P1, confidence 9/10]

`trigger_call()` needs to pass `provider_id` as metadata on the Vapi call so `webhook.py` knows which provider the transcript belongs to. Without it, `save_call_result()` has no provider association.

**Fix:** Add to Vapi payload:
```python
"metadata": {"provider_id": provider["provider_id"]}
```
Then in `webhook.py`: `provider_id = msg.get("call", {}).get("metadata", {}).get("provider_id", "")`

### Finding 3 — No NPPES API rate limit handling [P2, confidence 8/10]

The NPPES API limits requests. Fetching 500 in one call will likely hit a 429. The API returns max ~200 results per call.

**Fix:** Paginate: fetch in batches of 200, 3 requests total, add `skip` param. Or: cache to `nppes_sample.json` in hour 1 and never re-fetch.

### Finding 4 — SQLite write contention on webhook [P2, confidence 7/10]

Vapi can fire multiple `end-of-call-report` events for the same call. If two webhooks arrive close together, concurrent SQLite writes can corrupt the DB.

**Fix:** Use `INSERT OR REPLACE` (already in seed logic) for call results too. Add a `UNIQUE` constraint on `call_sid`. Accepted: SQLite's serialized write mode handles most cases, and demo has ≤10 concurrent calls.
